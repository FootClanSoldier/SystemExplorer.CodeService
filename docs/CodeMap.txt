SystemExplorer.CodeService Code Map
===================================

Current implementation
----------------------

This file describes the implementation in the current source tree. Roadmap and
Research remain architecture context; the C# source remains implementation source of
truth.

CodeServiceEntryPoint.cs
    CodeServiceEntryPoint
        Thin async composition/startup boundary.

        Parses startup arguments through CodeServiceStartupOptions, creates the
        CodeServiceHost, reports controlled startup failures to stderr, awaits host
        lifetime, and maps controlled failure categories to process exit codes.

        stdout is not used here. The only stdout writer in current source is
        BootstrapReadinessWriter.

        Current exit codes:

            0 = normal validated-owner lifetime completion
            1 = unexpected fatal runtime failure
            2 = invalid startup arguments
            3 = Godot owner validation failure
            4 = local transport startup failure
            5 = session/publication/control-plane startup failure
            6 = private Roslyn runtime provisioning failure on a supported packaged platform

Startup/
    CodeServiceStartupOptions.cs
        CodeServiceStartupOptions
            Immutable validated startup configuration for explicit server mode.
            Strictly parses:

                system-explorer-code server
                    --godot-pid <pid>
                    --godot-start-time-utc-ticks <ticks>
                    [--project-root <absolute-project-root>]
                    [--startup-document <project-relative-cs-path>]
                    [--diagnostic-log]
                    [--roslyn-runtime <absolute-directory>]

            --roslyn-runtime is optional and remains a strict development/test override.
            When present, parsing validates exactly the supplied absolute runtime directory
            and publishes an immutable RoslynLanguageServerRuntime descriptor with source
            identity ExplicitOverride. Invalid explicit runtime input fails closed during
            argument parsing and never falls back to the packaged runtime.

            When --roslyn-runtime is absent, startup composition delegates runtime choice to
            RoslynLanguageServerRuntimeResolver. The parser does not know AppContext.BaseDirectory,
            RID/tool-store layout or platform mapping.

            --project-root is an optional Service capability for backward compatibility. When
            present, parsing reuses WorkspaceIdentity.TryCreate so the startup value has exactly
            the same bounded, fully-qualified, Path.GetFullPath, trailing-separator and platform
            equality semantics as transport initialization. Duplicate, relative or malformed values
            fail startup parsing. The resulting immutable StartupWorkspaceIdentity is an
            authoritative workspace identity seed; existence and project.godot validation still
            occur at the first actual WorkspaceHost initialization.

            Intended System Explorer production composition supplies projectRoot exactly once to
            each newly launched Service through --project-root. After bootstrap and Service-owned
            startup workspace initialization, the client uses workspace.status observation and does
            not normally resend the same root through /workspace/initialize. A replacement Service
            after crash/retirement is a new process lifetime and receives the same root once at its
            own launch. Services intentionally launched without --project-root retain
            /workspace/initialize as the canonical explicit initialization API.

            --startup-document is optional process-start configuration only; it is not a protocol field. Structural CLI
            mistakes (missing value or duplicate option) remain invalid startup arguments. A present path is instead validated
            by StartupDocumentHint as a bounded project-relative forward-slash `.cs` wire path. Semantic rejection is nonfatal
            and stores only a bounded reason code; invalid raw path text is not retained for diagnostics. An otherwise accepted
            hint is rejected as project_root_missing when no accepted --project-root exists.

    StartupDocumentHint.cs
        StartupDocumentHint
            Immutable startup-only NotSpecified / Accepted / Rejected model. Accepted retains only the canonical
            project-relative path. Validation uses DocumentSynchronizationLimits.MaxDocumentPathLength and rejects empty/too-long,
            non-.cs, leading/trailing slash, backslash, colon/rooted paths, empty segments and `.`/`..` segments. Rejected retains
            only a bounded reason code.

    StartupDocumentWarmupModels.cs
        Internal scalar/result transport for speculative startup document seed and successful completion-readiness warm-up. It
        carries only DocumentIdentity/publication/Roslyn-generation/LSP-version/overlay/count correlation; it is not a transport
        schema and contains no source text or absolute path.

            Session publication/authentication adds no CLI flags.

Lifetime/
    GodotProcessIdentity.cs
        GodotProcessIdentity
            Immutable Godot owner identity:

                ProcessId
                StartTimeUtcTicks

    GodotProcessLifetime.cs
        GodotProcessLifetime
            Validates the supplied exact Godot PID/start identity and retains the
            originally opened Process instance for lifetime observation.

            Godot owner exit remains the sole normal CodeService shutdown authority.
            Client disconnect, handshake failure and plugin lifetime do not own host
            shutdown.

    ServiceProcessIdentity.cs
        ServiceProcessIdentity
            Immutable CodeService OS process identity:

                ProcessId
                StartTimeUtcTicks

            TryCaptureCurrent() explicitly captures identity once from
            Process.GetCurrentProcess() plus Process.StartTime.ToUniversalTime().Ticks.
            Environment.ProcessId is used only as a consistency check.

            The captured value is reused by diagnostics, descriptor publication,
            handshake and bootstrap readiness. Those subsystems do not independently
            re-resolve CodeService start identity.

Sessions/
    SessionIdentity.cs
        SessionIdentity
            Service-generated random session identity. Current SessionId is 16 random
            bytes rendered as 32 lower-case hexadecimal characters.

    SessionCredentials.cs
        SessionCredentials
            Owns the 32-byte / 256-bit cryptographically random authentication token.

            The token remains memory-owned as byte[]. Internal consumers obtain only a
            ReadOnlySpan<byte>. Descriptor publication encodes that span directly into
            a temporary stack char buffer; no permanent Base64 token string is cached.

            Matches(ReadOnlySpan<byte>) validates candidates through
            CryptographicOperations.FixedTimeEquals.

            Dispose is idempotent and zeroes the owned token bytes through
            CryptographicOperations.ZeroMemory before retiring the array reference.

    PerOwnerLaunchAuthority.cs
        PerOwnerLaunchAuthority
            Existing exact-owner launch arbitration remains unchanged.

            Owner key:

                exact Godot ProcessId + exact Godot StartTimeUtcTicks

            Claim path:

                owner_<pid>_<startTicks>.claim

            Contenders open the same per-user claim file and attempt immediate
            FileStream.Lock(0, 1). The retained FileStream/OS byte-range lock is the
            authority; file contents are not authority.

            The claim is held through descriptor removal and credential retirement.
            It is released last by SessionCoordinator retirement. Normal retirement
            deliberately does not delete the current claim file.

            The same Lock(0, 1) coordinates are centralized for Windows stale-claim
            deletion. Cleanup opens the exact existing claim, acquires that byte-range
            lock, and attempts File.Delete while the lock-owning stream remains open.
            Sharing/lock/delete failure preserves the artifact. This helper is
            destructive on Windows only.

            Current platform behavior remains:

                Windows/Linux
                    FileStream byte-range lock candidate.

                macOS/iOS/tvOS/FreeBSD
                    acquisition fails closed because current .NET FileStream.Lock
                    support is not accepted for this candidate.

    StaleLaunchAuthorityScavenger.cs
        StaleLaunchAuthorityScavenger
            Authoritative-startup-only, synchronous best-effort maintenance for
            Sessions/LaunchAuthority/*.claim. It scans TopDirectoryOnly and examines at
            most 4096 claim entries per startup. There is no worker, timer, polling loop,
            queue or service-lifetime authority.

            Only exact owner_<pid>_<startTimeUtcTicks>.claim names with invariant positive
            decimal identities are accepted. Malformed files are preserved and the
            current validated Godot owner claim is explicitly skipped.

            Each parsed foreign owner is probed by exact ProcessId + StartTimeUtcTicks
            using the same double-HasExited process-instance model as GodotProcessLifetime.
            ProcessName is never consulted. Observation is tri-state:

                ExactInstanceAlive
                    exact PID/start still alive -> preserve.

                ExactInstanceDead
                    PID absent, PID reused/start mismatch, or observed exited -> stale
                    candidate.

                Ambiguous
                    access/platform/process-observation uncertainty -> fail closed and
                    preserve.

            Temporary Process observations are deterministically disposed. On Windows,
            only a provably dead claim that PerOwnerLaunchAuthority can exclusively lock
            and delete under the existing sharing model is removed. On non-Windows,
            destructive stale-claim deletion is disabled in V1 because unlinking an open
            inode could break pathname rendezvous correctness; claims are preserved.
            The scavenger never touches descriptors, cache state, diagnostics or other
            session artifacts.

    SessionRuntimePathResolver.cs
        SessionRuntimePathResolver
            Resolves service-owned per-user session infrastructure outside the Godot
            project, current working directory and .NET Tool installation directory.

            Launch authority directory:

                <session-base>/LaunchAuthority/

            Descriptor directory:

                <session-base>/Descriptors/

            Deterministic descriptor path:

                <session-base>/Descriptors/
                    owner_<godotPid>_<godotStartTimeUtcTicks>.json

            Both Godot PID and Godot start identity are mandatory path identity.

            Session base resolution:

                Windows
                    %LOCALAPPDATA%/SystemExplorer/CodeService/Sessions/
                    with ApplicationData/UserProfile fallback if needed.

                macOS
                    ~/Library/Application Support/SystemExplorer/CodeService/Sessions/
                    with application-data fallback if needed.

                Linux/Unix
                    $XDG_RUNTIME_DIR/SystemExplorer/CodeService/Sessions/
                    when XDG_RUNTIME_DIR is absolute, otherwise
                    $XDG_STATE_HOME/SystemExplorer/CodeService/Sessions/
                    when XDG_STATE_HOME is absolute, otherwise
                    ~/.local/state/SystemExplorer/CodeService/Sessions/
                    with application-data fallback if needed.

    SessionDescriptorPermissions.cs
        SessionDescriptorPermissions
            Isolated restrictive descriptor-storage boundary.

            Unix-like implementation:

                descriptor directory creation mode = owner rwx (0700 semantics)
                descriptor temp-file creation mode = owner rw (0600 semantics)

                Directory.CreateDirectory(path, UnixFileMode) and
                FileStreamOptions.UnixCreateMode establish restrictive creation
                modes. File.SetUnixFileMode then normalizes the exact mode and
                File.GetUnixFileMode verifies it before token serialization proceeds.

            Windows implementation:

                current Windows user SID is resolved through WindowsIdentity
                descriptor directory is created with an explicit protected
                    DirectorySecurity DACL
                descriptor temp file is created with an explicit protected
                    FileSecurity DACL
                inherited access rules are disabled
                current user is owner
                only the current user receives FullControl
                resulting ACL/owner are read back and verified

                Creation uses the official System.IO.FileSystem.AccessControl
                FileSystemAclExtensions Create/CreateDirectory APIs so the token is not
                written into a broadly inherited file and secured only afterwards.

            Permission setup/verification fails closed. Descriptor publication does not
            continue if the required owner-only security boundary cannot be created or
            verified.

            No third-party dependency is present. Current csproj adds no new package
            reference for this subsystem.

            Platform runtime verification status for this delivered source must be
            established by actual target-platform tests; CodeMap does not claim that
            Windows/Linux/macOS permission behavior has been runtime-tested merely from
            static implementation.

    SessionDescriptorStore.cs
        SessionDescriptorStore
            Sole service-side descriptor serialization/publication/removal helper.

            Descriptor schemaVersion = 1.

            Complete descriptor fields:

                schemaVersion
                protocolVersion
                serviceVersion
                sessionId
                godotPid
                godotStartTimeUtcTicks
                servicePid
                serviceStartTimeUtcTicks
                transport
                address
                port
                authenticationToken

            Current transport values are:

                transport = "http"
                address   = "127.0.0.1"

            authenticationToken is the existing SessionCredentials token encoded as
            stable Base64 during serialization. The encoded chars live only in a
            temporary stack buffer and are cleared after writing.

            Maximum descriptor size = 16 KiB.

            Atomic publication sequence:

                resolve deterministic per-owner final path
                    -> establish/verify restrictive descriptor directory permissions
                    -> create unique temp file in the same descriptor directory
                    -> establish/verify restrictive temp-file permissions
                    -> write the complete JSON descriptor
                    -> Utf8JsonWriter.Flush()
                    -> FileStream.Flush(flushToDisk: true)
                    -> close temp stream
                    -> File.Move(temp, final, overwrite: true)

            The final descriptor path is never incrementally written. Replacement of
            an older descriptor for the same exact owner uses the same-directory
            overwrite/rename operation while launch authority remains held.

            A failed publication attempts best-effort removal only of its own unique
            temporary file. There is no temp-file scan or global stale-descriptor
            cleanup.

            Compare-before-delete:

                open current deterministic descriptor defensively
                    -> reject >16 KiB
                    -> read into a fixed 16 KiB + 1-byte bound
                    -> parse with bounded JsonDocument depth
                    -> reject malformed or duplicate ownership fields
                    -> require schemaVersion=1
                    -> require exact sessionId
                    -> require exact servicePid
                    -> require exact serviceStartTimeUtcTicks
                    -> only then File.Delete(finalPath)

            Malformed, oversized, unreadable, missing, replaced or identity-mismatched
            metadata never authorizes deletion. Descriptor cleanup exceptions are
            contained and reported as a removal result.

        SessionDescriptorRegistration
            SessionCoordinator-owned registration containing:

                DescriptorPath
                SessionIdentity
                ServiceProcessIdentity

            Registration exists only after atomic publication succeeds.

    SessionCoordinator.cs
        SessionCoordinator
            Owns one authoritative session after launch arbitration succeeds:

                Godot owner identity
                SessionIdentity
                SessionCredentials
                PerOwnerLaunchAuthority
                optional published SessionDescriptorRegistration

            PublishDescriptor(...) is explicit and one-shot. It delegates serialization
            and atomic publication to SessionDescriptorStore and records ownership only
            after publication succeeds.

            Retirement order is fixed:

                descriptor compare-before-delete
                    -> SessionCredentials.Dispose / token zeroing
                    -> PerOwnerLaunchAuthority.Dispose / OS lock release

            Descriptor deletion failure does not keep credentials alive and does not
            keep launch authority forever. Credential/authority retirement is still
            attempted in finally-style order.

            Descriptor cleanup status distinguishes removed, absent, ownership not
            proven and actual cleanup failure. Dispose remains idempotent.

            never returned.

Workloads/
    WorkloadCoordinator.cs
        WorkloadCoordinator
            Host-owned lifetime/admission boundary for expensive service work. It is
            transport-independent, Godot-independent and Roslyn-independent.

            Current declared lane identities:

                WorkspaceConstruction
                DocumentSynchronization
                SemanticReadiness
                Completion
                SemanticWarmup
                CompletionResolveWarmup

            Current verified conflict matrix from source is explicit/fail-closed for all
            36 ordered pairs:

                WorkspaceConstruction conflicts with every lane.
                DocumentSynchronization conflicts with WorkspaceConstruction and itself, but not
                    SemanticReadiness, Completion, SemanticWarmup or CompletionResolveWarmup.
                SemanticReadiness conflicts with WorkspaceConstruction, itself and Completion, but not
                    DocumentSynchronization, SemanticWarmup or CompletionResolveWarmup.
                Completion conflicts with WorkspaceConstruction, itself and SemanticReadiness, but not
                    DocumentSynchronization, SemanticWarmup or CompletionResolveWarmup.
                SemanticWarmup conflicts with WorkspaceConstruction and itself, but not DocumentSynchronization,
                    SemanticReadiness, Completion or CompletionResolveWarmup.
                CompletionResolveWarmup conflicts with WorkspaceConstruction and itself, but not
                    DocumentSynchronization, SemanticReadiness, Completion or SemanticWarmup.

            Every foreground lane remains immediate/no-queue and self-exclusive according to
            the matrix above. Document synchronization may overlap feature work so a newly committed
            Roslyn-visible overlay can cancel/supersede stale SemanticReadiness or Completion work.
            The generation-scoped startup-completion-readiness SemanticWarmup path may additionally overlap
            DocumentSynchronization and foreground Completion while that Completion awaits the shared readiness signal;
            it may also overlap one foreground SemanticReadiness during preemption/retirement. The readiness owner keeps
            at most one active SemanticWarmup attempt and one latest scalar candidate, never a warm-up queue.
            CompletionResolveWarmup may overlap DocumentSynchronization, SemanticReadiness, Completion and
            SemanticWarmup, but only one resolve warm-up may be active and WorkspaceConstruction remains conflicting.
            Before its RpcStarted point-of-no-return, foreground transport admission may cancel-signal the exact resolve
            warm-up attempt. After RpcStarted, ordinary Completion admission does not cancel or wait for
            CompletionResolveWarmup and may overlap it; only Service shutdown or a validated real foreground completion
            resolve may cancel-signal the in-flight resolve warm-up. Cancellation never implies SemanticWarmup or
            CompletionResolveWarmup retirement; each warm-up lease remains active until its owned async operation actually
            returns or faults.

            WorkspaceHost uses WorkspaceConstruction for complete initial construction and
            autonomous runtime dirty reconciliation. Transport document epoch/snapshot
            operations use DocumentSynchronization. Standalone SemanticReady uses
            SemanticReadiness. Completion owns Completion and calls Roslyn completion against the pinned private
            runtime's completion-specific current-source frozen-partial contract; it does not invoke or require the
            exact SemanticReady feature contract. During unresolved cold startup it may seed/join the separate
            generation-scoped StartupCompletionReadiness performance goal before the Roslyn completion RPC. Snapshot
            observation uses SemanticWarmup only after a successful snapshot response has completed and the
            DocumentSynchronization lease has retired; completion-side seeding independently closes the response/observer
            race. A successful completion response that actually publishes an import candidate may, only after
            response completion and Completion lease retirement, admit CompletionResolveWarmup for an owned
            opportunistic completionItem/resolve whose result is discarded. ProjectIndexHost and
            RoslynLanguageServerHost do not acquire nested lanes.

            Workspace-owned Roslyn-generation document replay is deliberately different:
            DocumentSynchronizationHost requires the already-owned WorkspaceConstruction
            WorkloadExecutionLease and does not acquire DocumentSynchronization again. This
            prevents self-Busy/deadlock while still excluding transport document mutation.

            There is no expensive-work Channel, queue, worker backlog or Task.Run worker pool.
            Capacity is one conflicting operation with zero queued expensive operations.
            Runtime filesystem activity remains bounded cheap dirty intent until a quiet timer
            obtains WorkspaceConstruction admission.

            Admission is immediate and explicitly typed:

                free exclusive lane
                    -> Admitted + WorkloadExecutionLease

                occupied exclusive lane
                    -> Busy

                coordinator shutdown/retirement started
                    -> ShuttingDown

            Busy is immediate. Runtime reconciliation retains its cheap pending dirty intent
            for a later debounce attempt; document transport receives a bounded Busy outcome.

            WorkloadExecutionLease carries scalar lane + operationId identity and the
            service-work shutdown CancellationToken. Lease retirement is idempotent and
            only the exact currently owned operation may release its lane.

            Core retirement invariant:

                cancellation requested
                    !=
                lane retired

            BeginShutdown() closes admission while holding coordinator state ownership,
            then signals the service-work CancellationToken only after releasing the
            lock. Cancellation callbacks therefore cannot admit new expensive work and
            cannot run under the coordinator lock. Cancellation alone never clears an
            active lane.

            An active lane remains owned until the corresponding execution lease is
            explicitly retired after the expensive operation actually returns or faults.
            Runtime reconciliation retires its lease in finally only after candidate
            publication/fault handling and operation-ownership cleanup are terminal.
            RetireAsync() waits for all active leases to retire before disposing the
            coordinator-owned cancellation source and reaching terminal state.


Documents/
    DocumentSynchronizationLimits.cs
        Central explicit bounds for the ephemeral document domain: 256 declared open
        documents, 2048-character wire paths, 3 MiB decoded UTF-8 text per snapshot,
        64 MiB total retained snapshot bytes, 1 MiB epoch request bodies and 16 MiB
        snapshot request bodies. Open snapshots are not evicted while declared open.

    DocumentIdentity.cs
        Workspace-relative normalized C# document identity. Wire format uses '/' only and
        rejects rooted/drive-qualified paths, backslashes, leading/trailing slash ambiguity,
        empty/dot/dot-dot segments and non-.cs extensions. The resolved path must remain
        contained under WorkspaceIdentity. Equality is Windows OrdinalIgnoreCase and
        non-Windows Ordinal. When current WorkspaceProjectSnapshot.SourceFiles contains the
        path, its snapshot spelling becomes the canonical DocumentIdentity path; request
        casing is never canonical authority.

    DocumentSynchronizationModels.cs
        Authority/version vocabulary is deliberately separated:

            ClientGeneration
                monotonic managed/client-composition ordering authority
            EpochId
                canonical GUID identity within exactly one ClientGeneration
            ClientVersion
                positive monotonic editor/document version within authority + document
            WorkspacePublicationIdentity
                exact workspace publication correlation
            RoslynGeneration
                exact Roslyn process generation
            RoslynLspVersion
                positive process-generation-local LSP document version

        DocumentSynchronizationDocumentSnapshot is an internal immutable scalar snapshot for
        future feature admission. It exposes no source text and does not imply SemanticReady.

    DocumentSynchronizationHost.cs
        CodeServiceHost-owned bounded in-memory document state owner. It has non-owning
        WorkloadCoordinator and RoslynLanguageServerHost references. WorkspaceHost and
        LocalTransportHost have non-owning references to this host.

        Current authority is exactly ClientGeneration + EpochId. Lower client generations
        are StaleEpoch and can never retake authority. Same generation with a different epoch
        is EpochConflict. A higher generation is a monotonic takeover barrier; retained open
        paths keep their best-known stored overlay but reset accepted client version to 0 and
        HasCurrentAuthoritySnapshot=false until the new authority confirms a full snapshot.

        /documents/epoch reconciles the declared-open set idempotently. A syntactically valid
        contained C# path may be declared open before it appears in current SourceFiles.
        Removed tracked overlays are didClose'd when they are open in the exact current Roslyn
        generation, then their stored text is removed. Terminal service shutdown does not
        mass-send didClose; disposal simply clears all ephemeral source memory and authority.

        /documents/snapshot requires current authority, declared-open membership and exact
        current SourceFiles membership. Lower ClientVersion is StaleVersion; equal version plus
        equal text is AlreadyCurrent; equal version plus different text is VersionConflict.
        A first accepted overlay sends didOpen with RoslynLspVersion=1. Changed text sends a
        full-content didChange with the next independent RoslynLspVersion. Identical text at a
        newer ClientVersion re-correlates without Roslyn churn, including managed-generation
        takeover. Candidate state is committed only after required Roslyn send success.

        Diagnostic logging v4 enriches existing document_sync_snapshot_accepted with
        workloadOperationId plus monotonic phase timing for pre-Roslyn validation, outer Roslyn
        send observation, state commit, overlay cancellation signaling and total snapshot pipeline.
        The same event records roslynNotificationKind as only None/DidOpen/DidChange and, when a
        Roslyn-visible notification occurred, the Roslyn host sender-capture, notification-await,
        post-send generation validation and total send durations. Existing document_sync_document_closed
        likewise carries workloadOperationId plus the same inner Roslyn didClose send timings when a
        close notification was required. Source text is never logged. These fields are observability-only;
        didOpen/didChange/didClose ordering, overlay revision advancement and cancellation authority are
        unchanged.

        Source text is retained only in bounded service memory. It is never written to index
        cache/session/runtime artifacts, never returned by a public status endpoint and never
        included in diagnostic details.

        Workspace-owned ReconcileRoslynGenerationAsync requires an existing
        WorkspaceConstruction lease. Reusing the same healthy Roslyn generation only
        re-correlates publication identity. A new ProjectLoaded generation sequentially replays
        each declared-open tracked current-source snapshot with didOpen version 1 from memory.
        Non-members remain retained but not open in Roslyn. Disabled/Faulted Roslyn performs no
        document traffic and preserves indexing-only Workspace Ready behavior. Replay failure
        stops remaining sends; Roslyn fail-closes and WorkspaceHost reacquires the final Roslyn
        snapshot before candidate publication.

        Current foundation status:

            permanent Roslyn runtime provisioning       yes
            Roslyn ProjectLoaded                       yes
            document identity                          yes
            document synchronization client authority yes
            full snapshot synchronization              yes
            didOpen/didChange/didClose                 yes
            service stale-version rejection            yes
            Roslyn generation document replay          yes

            SemanticReady                              no
            completion                                 no
            diagnostic feature                         no

Workspace/
    WorkspaceIdentity.cs
        WorkspaceIdentity
            Explicit normalized workspace identity. The identity is the absolute Godot
            project root after Path.GetFullPath plus redundant trailing-separator removal
            without damaging a filesystem root. Input is bounded to 4096 characters and
            must be fully qualified.

            Transport-first identity establishment additionally requires an existing directory
            with project.godot directly in the root before construction is admitted. A startup
            --project-root may seed the normalized identity earlier, but this does not mark the
            root validated: the first actual startup/transport initialization still performs the
            same Directory.Exists + project.godot validation. Path/normalization failures remain
            controlled before construction begins.

            Equality is explicit and platform-aware:

                Windows     OrdinalIgnoreCase
                other OS    Ordinal

            No random WorkspaceId or symlink/realpath canonicalization exists.

    WorkspaceProjectPathClassifier.cs
        WorkspaceProjectPathClassifier
            Shared discovery/FileSystemWatcher path policy. Project-relative paths use
            '/' separators and platform-correct comparison (Windows case-insensitive,
            non-Windows case-sensitive). C# source (*.cs), project (*.csproj) and
            solution (*.sln, *.slnx) metadata are classified explicitly; project.godot
            is recognized as workspace metadata for watcher Changed events.

            IsPathWithinPrunedTree() identifies any path containing a pruned directory
            component:

                .godot
                bin
                obj
                .git
                .vs

            plus the exact subtree:

                addons/system_explorer/**

            WorkspaceProjectDiscovery reuses
            WorkspaceProjectPathClassifier.ShouldPruneDirectory, while runtime filesystem
            observation reuses IsPathWithinPrunedTree from the same policy. Other addon
            trees remain normal project domain and are not blanket excluded.

    WorkspaceDirtyIntent.cs
        WorkspaceDirtyIntent / WorkspaceDirtyBatch
            WorkspaceHost-owned bounded coalesced filesystem intent. In addition to dirty
            version/signal count and ProjectIndexReconciliationHints, each batch carries one
            ForceRoslynProjectReload scalar. The flag is sticky within a pending batch and
            is never a queue. Conservative observer fallback promotes both full source
            validation and Roslyn project reload. Source-path hints remain bounded at 4096.

    WorkspaceFileChangeObserver.cs
        WorkspaceFileChangeObserver
            One FileSystemWatcher per active WorkspaceGeneration. Changed events for *.cs,
            *.csproj, *.sln, *.slnx and project.godot remain workspace-relevant. A normal
            *.cs content Changed event does not force Roslyn generation replacement.
            *.csproj/*.sln/*.slnx content Changed sets ForceRoslynProjectReload because path
            inventory alone cannot reveal project/reference/include metadata changes.
            Overflow/fault and other conservative fallback also force Roslyn project reload.

Indexing/
    IndexCacheFormat.cs
        IndexCacheFormat
            Internal persistent-cache compatibility constants, separate from ProtocolVersion
            and WorkspaceSchemaVersion. CacheFormatVersion is 2 and is the compatibility epoch
            for the persistent generation contract as a whole: current pointer, manifest,
            shards, generation semantics, deterministic routing contract and authority-aware
            persistence contract. CurrentPointerSchemaVersion, ManifestSchemaVersion and
            ShardSchemaVersion remain 1 because those JSON object shapes are unchanged.
            ShardPartitionerVersion remains 1 and the physical partitioner still uses exactly
            64 logical shards. Future incompatible persistent-cache revisions bump
            CacheFormatVersion, not physical directory names; individual backward-compatible
            JSON-shape changes bump only the applicable schemaVersion when appropriate.
            Defensive bounds are 4 KiB current.json, 64 MiB manifest, 64 MiB per shard
            and 250,000 source entries.

    IndexCachePathResolver.cs
        IndexCachePathResolver / WorkspaceCacheLocation
            Resolves persistent performance state outside the Godot project, session runtime
            directory and tool installation. The authority-aware workspace namespace is the
            stable, non-versioned Workspaces/managed/<WorkspaceKey>/ path. `managed` describes
            the process-external coordination domain; it is not a cache version and must not
            be renamed or nested when CacheFormatVersion advances. Workspace directory is
            keyed by the unchanged stable 64-lowercase-hex SHA-256 WorkspaceKey over canonical
            WorkspaceIdentity. Windows canonicalizes slash/backslash separators to one
            separator and folds case. Non-Windows hashes the already-normalized
            WorkspaceIdentity.ProjectRoot without changing path characters or case; a literal
            backslash remains a filename/path character and is not treated as a directory
            separator. A resolved cache path that would fall inside the Godot project is
            rejected and indexing falls back to memory-only persistence state.

            Current roots:

                Windows
                    %LOCALAPPDATA%/SystemExplorer/CodeService/Cache/Workspaces/managed/<WorkspaceKey>/

                macOS
                    ~/Library/Caches/SystemExplorer/CodeService/Workspaces/managed/<WorkspaceKey>/

                Linux
                    $XDG_CACHE_HOME/SystemExplorer/CodeService/Workspaces/managed/<WorkspaceKey>/
                    or ~/.cache/SystemExplorer/CodeService/Workspaces/managed/<WorkspaceKey>/

            Two older namespaces remain deliberately outside current active cache access.
            Pre-authority Workspaces/<WorkspaceKey>/ is never read, migrated, written or
            destructively scavenged because older writers do not know maintenance.lock. The
            transitional development Workspaces/v2/<WorkspaceKey>/ layout is also never read,
            merged, written or destructively retired by current source; directory-level
            retirement while another already-running transitional service may own its lock
            requires a separate coordination design. Workspaces/managed/ is therefore the one
            permanent directory-level compatibility boundary. WorkspaceCacheLocation exposes
            the permanent <WorkspaceCache>/maintenance.lock rendezvous path inside it.

    IndexShardPartitioner.cs
        IndexShardPartitioner / IndexPathValidation
            Stable source-path routing. Normalized project-relative source path is
            platform-canonicalized, SHA-256 hashed, converted to a deterministic UInt32
            and modulo 64. Content changes never move a source to another shard and adding
            unrelated files never repartitions existing sources. string.GetHashCode is
            not used. Cache-provided relative paths and filenames are strictly contained.

    SourceFileFingerprint.cs
        SourceFileFingerprint
            Cheap source metadata preflight reads Length + LastWriteTimeUtcTicks +
            deterministic ShardId without reading source contents. Candidate source
            fingerprinting streams raw bytes asynchronously through IncrementalHash
            SHA-256 using a pooled bounded buffer and FileShare.ReadWrite|Delete.

            Each hashed file compares length/mtime before and after the read and retries
            at most three times if the editor changes it during hashing. The
            service-work shutdown token is checked between reads. Source contents are
            never retained or persisted.

    WorkspaceCacheAuthority.cs / WorkspaceCacheAccess.cs
        WorkspaceCacheAuthority / WorkspaceCacheAccess
            ProjectIndexHost-owned process-external persistence boundary.
            WorkspaceCacheAuthority owns the analyzer-visible capability guard for its
            FileStream byte-range-lock primitive; WorkspaceCacheAccess consults that same
            capability before choosing coordination mode, and TryAcquire defensively
            revalidates it before touching the primitive. On the same platform scope where
            the current byte-range lock primitive is considered usable (including Windows
            and Linux), acquisition opens the permanent managed-workspace maintenance.lock
            with OpenOrCreate, ReadWrite and FileShare.ReadWrite, then locks byte range
            [0,1). The FileStream remains owned until ProjectIndexHost.Dispose; file existence
            has no authority meaning and the rendezvous file is never deleted on release.
            Acquisition is immediate/bounded with no polling, timeout loop, timer or
            background task.

            CacheCoordinationMode semantics are:

                CoordinatedExclusive
                    read=yes, write=yes, GC=yes

                LegacyUncoordinatedNoGc
                    read=yes, write=yes, GC=no

                Unavailable
                    read=no, write=no, GC=no

            Current explicit unsupported/uncertain byte-range-lock platforms (macOS, iOS,
            tvOS and FreeBSD) follow the launch-authority policy and retain legacy immutable
            publication semantics but never destructive GC. On a coordinated platform, failure
            to acquire the exact workspace authority degrades that ProjectIndexHost to MemoryOnly;
            it does not read current.json, retain shared persistent shard paths, publish or collect.
            The current implementation keeps that unavailable decision for the host lifetime
            rather than polling/retrying the lock. CacheFormatVersion does not participate in
            authority identity: every current/future format in the managed namespace uses the
            same <WorkspaceKey>/maintenance.lock before persistent read, write or GC.

    IndexCacheStore.cs
        IndexCacheStore
            Strict bounded cache reader and crash-safe publisher. Persistent read/write APIs
            now require WorkspaceCacheAccess, making authority/access policy compile-visible.
            Readers reject comments, trailing commas, duplicate/unknown required-object
            properties, invalid schema versions, duplicate source/shard identities, traversal
            filenames, malformed hashes/generation IDs and inconsistent routing. Cache files
            are size-checked before bounded reads. Persistent-path shard loads must resolve to
            the exact current access object's managed shards directory. current.json parsing
            keeps strict schema/shape/identity validation but exposes its cacheFormatVersion to
            the caller. A well-formed pointer from another compatibility epoch returns
            IncompatibleFormat(observedVersion) before any manifest or shard is read. If the
            pointer says the expected format, manifest and loaded shards must also carry the
            expected CacheFormatVersion; a mixed-format generation is Invalid rather than
            partially migrated.

            Stable disk layout:

                Cache/Workspaces/managed/<WorkspaceKey>/
                    maintenance.lock
                    current.json
                    manifests/manifest_<GenerationId>.json
                    shards/shard_<ShardId>_<GenerationId>.json

            current.json, manifests and shards all serialize cacheFormatVersion=2 while their
            individual schemaVersion values remain 1. No format prefix is added to filenames
            and no version subdirectory exists under Workspaces, manifests or shards.

            The publisher writes only the shard set explicitly supplied by ProjectIndexHost.
            Normal persisted-baseline reconciliation supplies changed non-empty shards;
            MemoryOnly recovery publication may also supply reusable in-memory shards needed
            to make the candidate disk manifest self-contained. Each supplied shard is
            serialized to its own unique same-directory .shard_*.tmp file with
            FileMode.CreateNew, fully flushed including Flush(flushToDisk: true),
            size-validated, then atomically promoted with overwrite=false to its immutable
            shard_<...>.json final name. The manifest follows the same unique
            .manifest_*.tmp -> durable flush -> bounded validation -> overwrite=false
            immutable final promotion after all supplied shards. current.json remains the
            sole published-generation pointer: it is written to a unique same-directory temp,
            durably flushed and atomically moved/overwritten LAST.

            Failed shard/manifest/current operations still clean only the exact temporary
            file owned by that publication operation. A process crash may leave orphan temps
            or complete unreferenced immutable candidates; retirement is a separate bounded
            authority-owned maintenance responsibility.

            A manifest may reference changed shards from its own generation and unchanged
            shards from older generations. Liveness is therefore filename reachability from
            the exact current manifest, never shard generation equality.

    IndexCacheGarbageCollector.cs
        IndexCacheGarbageCollector
            Separate retention/maintenance component. Its public maintenance call requires a
            WorkspaceCacheAccess that proves CoordinatedExclusive authority. Before any delete
            it bounded-reads/parses current.json through IndexCacheStore, verifies it still
            names the trusted in-memory current manifest generation and expected manifest
            filename, verifies the live manifest final exists, verifies every live shard final
            exists, and rejects reparse-point/symlink maintenance directories. Any mismatch
            deletes nothing.

            Retention roots are exactly:

                live manifest
                    manifest_<trusted current GenerationId>.json

                live shards
                    exact trustedCurrentManifest.Shards[].FileName set

            It streams only top-directory files under manifests/, shards/ and the exact
            workspace root. Strict retired manifest finals are swept first; only if that pass
            completes does shard sweeping begin. Strict unreferenced shard finals are then
            removed, preserving mixed-generation shard references exactly. Strict owned
            .manifest_*, .shard_* and .current_* orphan temps are best-effort deleted; unknown
            names/future artifacts are preserved. No directories are deleted and there is no
            recursion.

            One pass examines at most 4096 entries per scanned directory and performs at most
            2048 deletes total. Enumeration is streaming; no full-directory ToArray/ToList is
            materialized. Bound exhaustion sets Truncated=true so a later publication/startup
            maintenance pass can continue. IO/access/security/path deletion failures are
            counted and contained. A retired final-manifest delete failure stops that pass
            before shard sweeping, avoiding a leftover retired manifest whose shards were
            removed; shard/temp delete failures remain best-effort. Cancellation returns a
            Canceled summary rather than escaping into index publication. There is no
            maintenance workload lane, queue, Task.Run, timer, polling loop or per-file log.

            Maintenance cadence is event-driven only: at most one pass during successful warm
            initialization/generation reuse and one pass after each successful persistent
            publication. Runtime duplicate/no-op and MemoryOnly results perform zero GC.
            Publication timing remains IndexCacheStore.TryPublishAsync-only; GC duration is
            reported separately.

            only after a trustworthy previous shard hash comparison differs. Local shard
            rebuild therefore increments rebuiltShards/fingerprintedSources but does not
            guess content change. affectedShards counts logical mutation plans,
            baselineShardLoadAttempts counts actual baseline fetches, inMemoryShardLoads and
            persistentShardLoadAttempts are subsets, and rewrittenShards counts changed
            non-empty shard payloads in the candidate. generationReused is true only when
            the exact existing logical generation is retained (including unchanged warm
            persistent startup and runtime duplicate/no-op); metadata-only generation changes
            therefore report false even with rewrittenShards=0. cacheWriteAttempted means
            TryPublishAsync was actually invoked, cacheWriteSucceeded means that invocation
            returned Persisted, and persistenceState is the resulting Persisted/MemoryOnly
            generation state.

            Monotonic timings cover inventory, persistent current-cache load, actual
            fingerprint calls, baseline shard loads, actual TryPublishAsync publication and
            whole-operation total duration. The reached pipeline phase is a typed internal
            enum rather than an arbitrary diagnostic string. Persistence telemetry distinguishes write
            attempted/succeeded, Persisted versus MemoryOnly result and bounded
            persistence-unavailable incidents. At most the first persistence-unavailable
            incident writes a breadcrumb per operation; subsequent incidents remain scalar
            summary counts.

    ProjectIndexHost.cs
        ProjectIndexHost
            WorkspaceHost-owned, transport/Godot/Roslyn-independent index lifetime owner.
            Explicit state is Uninitialized -> Reconciling -> Ready with Faulted and
            ShuttingDown. It owns current immutable ProjectIndexGeneration plus a scalar
            reconciliation/publication generation guard. It owns no workload lane, watcher,
            timer, queue or polling loop.

            Initial process startup path:

                Build source metadata inventory
                    -> resolve cache and read current.json + manifest when available
                    -> exact metadata + no stronger hints
                        -> exact warm persistent generation
                        -> no source hash/shard read/cache write
                    -> otherwise reconcile or cold-build

            Runtime path is separate:

                ReconcileCurrentAsync
                    -> capture exact current in-memory ProjectIndexGeneration baseline
                    -> never reread current.json to choose the baseline
                    -> rediscovered source metadata inventory
                    -> exact metadata + no hints => return exact current generation
                    -> otherwise classify Added / Deleted / PotentiallyModified
                    -> union forced source hints or full-validation fallback
                    -> group mutations by ShardId
                    -> load each affected baseline shard at most once
                    -> prefer exact InMemoryShard, otherwise its stored persistent path
                    -> hash only added/evidence-backed/metadata-changed sources

            If a forced fingerprint proves identical bytes and metadata is still exact,
            the exact current ProjectIndexGeneration is reused: no new generation, manifest
            or current.json. Same-content metadata touches still publish only a new manifest
            + current pointer. Actual byte changes rewrite only affected shards. Added and
            Deleted sources retain deterministic shard routing. Full validation hashes all
            existing sources but still rewrites only shards whose content actually changed.

            Candidate state is private until complete. Runtime candidate failure restores
            ProjectIndexHost to the previous Ready generation; WorkspaceHost decides whether
            the failure was superseded or must fail the workspace closed. Shutdown invalidates
            publication so stale work cannot publish after ShuttingDown wins.

            MemoryOnly generations are first-class runtime baselines. Affected in-memory
            shards are read directly. Unchanged shard snapshots are carried forward as the
            exact baseline ProjectIndexShardSnapshot, so a later pass never fabricates a
            persistent path for state that was never published. Persistent publication is
            retried best-effort; reusable memory-backed shards are included when needed for
            a coherent disk manifest. Publication failure still yields a coherent MemoryOnly
            generation composed of new in-memory changed shards plus exact reusable baseline
            storage.

            Missing/corrupt affected persistent shard state triggers only that shard's local
            rebuild. Persistent cache remains performance state, never source authority.
            Persistent CacheFormatVersion is 2 while current-pointer/manifest/shard JSON
            schemas and ShardPartitionerVersion remain 1. Physical layout is the stable
            authority-aware Workspaces/managed/<WorkspaceKey>/ namespace and ProjectIndexHost
            owns one WorkspaceCacheAccess for its exact workspace identity.
            On coordinated platforms the authority lock is retained across runtime
            reconciliations, Faulted -> explicit retry and managed client reconnect, is not
            released by BeginShutdown, and is detached/disposed only by ProjectIndexHost.Dispose
            after WorkloadCoordinator actual drain. Cache access is acquired outside _sync.

            Initialization establishes managed workspace cache access before persistent load.
            A coordinated authority holder may warm-load and persist; a same-workspace secondary service that
            cannot acquire authority cold-builds/continues with MemoryOnly state and cannot
            fabricate shared persistent paths. Unsupported coordination platforms may keep the
            prior immutable uncoordinated read/write semantics but cannot run GC.

            A current-pointer CacheFormatVersion mismatch is a clean cold-rebuild condition,
            not corruption or persistence unavailability: no old manifest/shards are loaded,
            ProjectIndexHost reports cacheLoadStatus=IncompatibleFormat, emits the sparse
            index_cache_format_incompatible breadcrumb with observed/expected versions when
            diagnostics are enabled, and builds from source. On successful publication the new
            current-format pointer switches LAST and normal reachability GC retires unreachable
            older-format finals. Publication failure before the current switch performs no GC,
            so the previous-format current generation remains authoritative.

            Successful persistent publication is now:

                immutable changed/materialized shards
                    -> immutable manifest
                    -> durable current.json swap LAST
                    -> bounded authority-owned retention GC

            GC uses the just-published manifest as trusted current and preserves every exact
            shard filename it references, including shards from older generation IDs. Warm exact
            initialization and initialization validation that returns the exact persisted
            baseline may run one bounded maintenance pass without changing warm index counters:
            zero source hashes, zero shard reads, zero cache publication writes, generation
            reused. Normal runtime no-op never scans cache directories.

            With diagnostic logging enabled, each index operation exposes sparse correlated
            breadcrumbs/summary rather than per-source or per-shard lifecycle spam. Boundaries
            include preflight start/completion, reconciliation start/planning, actual
            publication start, current-generation publication, terminal completion, cancel
            and fault. Terminal summary identifies ColdBuild, WarmReuse, Reconciled or
            GenerationReuse and reports source/reconciliation/shard counters, cache-load
            status, persistence outcome and monotonic phase timings. Warm exact reuse keeps
            zero hashes/shard reads/cache writes and does not emit a false new-generation
            publication breadcrumb; runtime duplicate/no-op likewise proves exact generation
            reuse without publication. Same-content metadata touch remains a manifest/current
            metadata generation with zero rewritten shards; MemoryOnly success is not reported
            as workspace fault.
            Fault/cancel records contain only partial scalar telemetry reached before the
            terminal boundary. Resource snapshots are best-effort and taken only at coarse
            terminal diagnostics boundaries. Cache authority emits only establishment-state
            breadcrumbs (acquired or unavailable). Maintenance emits one typed
            index_cache_gc_completed or index_cache_gc_skipped summary per actual pass with
            trigger, current generation, examined/deleted counters, delete failures,
            truncation and independent duration; no per-file delete events are written.

            ProjectIndexHost still owns no SymbolMap, syntax/type/member payload, Roslyn or
            feature API. Roslyn and document synchronization are separate production owners.

            methods on any implemented exact route return zero-body HTTP 405. No request
            can stop CodeService or change logging/session lifetime state.

            Authentication contract:

                Authorization: Bearer <base64-token>

            Exactly one Authorization header value is required. The complete expected
            header length is bounded by the known 32-byte token Base64 length. The
            Bearer scheme is matched case-insensitively, Base64 is decoded into a fixed
            32-byte stack buffer, decoded length must be exactly 32 bytes, and
            SessionCredentials.Matches performs fixed-time comparison. The temporary
            decoded buffer is zeroed after comparison.

            Missing, duplicate, malformed, oversized or wrong credentials return:

                HTTP 401 Unauthorized
                Content-Length: 0
                no diagnostic token detail

            After authentication, handshake requires:

                no positive Content-Length
                no Transfer-Encoding/chunked body

                X-SystemExplorer-Protocol-Version
                    invariant integer
                    must equal ProtocolVersion=1

                X-SystemExplorer-Session-Id
                    bounded single value
                    exact ordinal match to current SessionId

                X-SystemExplorer-Request-Id
                    bounded single value
                    Guid "D" representation

            Authenticated failure mapping:

                malformed/missing body-or-context requirement
                wrong session ID
                    -> HTTP 400 + { outcome: "InvalidRequest", ... }

                valid request with protocol-version mismatch
                    -> HTTP 409 + { outcome: "VersionMismatch", ... }

            Valid authenticated handshake:

                HTTP 200 + HandshakeResponse

            Response endpoint fields come from the same verified BoundEndpoint that was
            published in the descriptor. Response owner/service/session identities come
            from the same SessionProtocolContext values used by publication/bootstrap.

            Handshake wire validation/order and success/failure schema remain unchanged.

            Both workspace routes reuse the same Bearer authentication implementation and
            require the same bounded protocol/session/request headers. Protocol mismatch
            returns HTTP 409 VersionMismatch; malformed/session mismatch returns controlled
            InvalidRequest JSON after authentication.

            /workspace/initialize accepts a bounded strict JSON object only:

                { "schemaVersion": 1, "projectRoot": "<absolute path>" }

            Required properties must each occur exactly once, unknown properties,
            comments and trailing commas are rejected, projectRoot must be a bounded JSON
            string, and workspace schema mismatch returns VersionMismatch. Body reading
            uses RequestAborted only before workspace construction admission. Once admitted,
            WorkspaceHost uses the WorkloadExecutionLease service-shutdown token instead.

            /workspace/status requires no body and returns a cheap coherent read-only status
            snapshot for Uninitialized/Initializing/Indexing/Ready/Faulted/ShuttingDown without
            taking the WorkspaceConstruction lane or touching cache/filesystem state. Normal status
            reads return HTTP 200 Success even when the workspace lifecycle state is Faulted; for
            example an invalid startup root is observed as state=Faulted with
            faultKind=InvalidProjectRoot. Here Success describes the status-query operation, while
            state/faultKind describe workspace lifecycle failure. ShuttingDown remains queryable as
            HTTP 503 Unavailable with state=ShuttingDown.

            Workspace initialize HTTP mapping is:

                200 Success
                400 InvalidRequest
                409 VersionMismatch / WorkspaceMismatch
                503 Busy / Unavailable
                500 Faulted

            Document routes reuse the same authentication and protocol/session/request-id
            headers but use DocumentSynchronizationSchemaVersion=1 independently from
            WorkspaceSchemaVersion. Inbound JSON is parsed explicitly with JsonDocument:
            exact properties only, duplicate rejection, integer type checks, canonical GUID-D
            epochs, comments/trailing commas disabled and bounded depth. /documents/epoch is
            capped at 1 MiB and /documents/snapshot at 16 MiB; bounded stream reading also
            enforces those caps when Content-Length is absent. Decoded snapshot text is capped
            at 3 MiB UTF-8 before document admission. The existing workspace initialize parser
            keeps its 8 KiB cap, while handshake/workspace.status continue to reject any body.

            Both document routes acquire the conflicting DocumentSynchronization workload lane
            before capturing WorkspaceHost.TryGetCurrentPublication. They never construct a
            workspace, start Roslyn or trigger indexing. RequestAborted is linked with the
            lease's service-shutdown token for request-scoped work, and the lease retires only
            in finally after the actual document operation reaches its terminal boundary.

            Document HTTP mapping is explicit: Success/AlreadyCurrent=200, InvalidRequest=400,
            version/epoch/document conflicts=409, CapacityExceeded=413 and Busy/workspace or
            Roslyn unavailable/unavailable=503. Source text is never returned.

            Authentication failure remains zero-body HTTP 401 and wrong methods remain
            zero-body HTTP 405. Request/response faults remain contained inside the
            transport request boundary.
